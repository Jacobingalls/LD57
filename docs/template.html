    The progression spine

    Depth = progress

    Going "deeper" is literal: the camera scrolls down a pit. Each idle module you buy unlocks a new layer of mechanics — New Gloomhollow (people), the Refining Crystal, the Library/distillery (research), and finally the Gate. The theme of LD57 was "deeper"; the game takes it at face value.

    The turn

    From idle game to horror

    It plays as a cozy incremental until the gate research (Investigate → Study → Understand) reveals the truth: the seal opens only by feeding mortal souls into it. The endgame is an industrialized sacrifice line — a Ritekeeper hurling townsfolk down the pit you spent the whole game digging.

    ⌖ Reading this atlas Every section is a faithful map of the existing Unity game plus a green-tinted porting note where the web target diverges. Numbers come straight from source — costs and formulas are hard-coded in UpgradeManager.cs, so the balance below is exact, not estimated.
    Stratum I · skeleton

    Architecture & the event bus

    A handful of singleton managers own state; everything else is decoupled through JamKit's PubSub — a global string-keyed event bus. Most wiring ("when X is published, call Y") lives in the Unity scene, not in code.

    State owners (singletons)
    • ResourceManager — the 4 resources + the additive/multiplicative modifier stacks.
    • UpgradeManager — all 29 upgrades, costs, requirement graph, purchasing.
    • MakoManager — orb spawning, the live orb list, orb→resource conversion.
    • PeopleManager — housing, passive generation, the sacrifice cadence.
    • LD57GameManager — thin glue (tooltip prefab, BGM); JamKit's own GameManager drives scene loads.
    JamKit — the framework layer

    A custom game-jam toolkit (info.jacobingalls.jamkit, pulled from GitHub). It is the single biggest thing a port must replace:

    • PubSub — PubSubSender.Publish(key) / scene PubSubListeners. The nervous system.
    • AudioManager — a 64-source pool, mixer volumes in PlayerPrefs.
    • GameManager — additive scene loading + loading screen.
    • UI kit — StandardButton, PauseMenu, SettingsPanel, Tabs, title-screen helpers (incl. DeleteIfWebGL).
    • ObjectPooler, ValueAnimator, Spin — small utilities.
    ⚠ No save system A grep for PlayerPrefs game-state / JsonUtility / serialization comes back empty. State lives only in DontDestroyOnLoad singletons for the session. Refreshing the page loses everything. Only audio volumes persist. For the sequel this is a clean slate — a port can add proper save/load without untangling legacy formats.
    Stratum II · the engine

    The Mako pipeline

    "Mako" is the internal name for the substance (an FF7 nod). One orb's journey from the pit to your wallet is the entire early game — and it is real 2D physics, not a particle effect.

    ✦ The pink cloud is real There is no Unity ParticleSystem anywhere in the project. The dense "Mysterious Substance" cloud in the screenshots is hundreds-to-thousands of live MakoOrb rigidbodies, each with a collider, corralled around the harvester by a ResourceField that pushes them up and toward a center axis. This is the single most important rendering fact for the port: you must batch-render and pool many physics entities, not fake a GPU emitter.
    Manual control

    Charge to nine

    The harvester holds a 0→9 charge. Tap (or hold, once Divine Guidance is bought) adds manualClickGain — ×2 per Calibration. At 9 it fires a laser; 0.25s later SpawnMakoOrbs() births 1–N orbs and the charge resets. Divine Warrior adds Space/C keyboard control.

    Idle / automation

    Mortals at the machines

    Channelers (auto-harvesters, max 8) tick the shared charge every ~1.0s. Manifest Pylons (auto-collectors, max 6) run a ~2s cooldown loop, each pulling the nearest collectable orb with a PD seek controller (maxVel = 4 × 2^upgrades). Every upgrade simply flips on one pre-placed, inactive machine in the scene.

    Anti-deadlock safeties (port these or orbs pile up)

    • A held orb's collider is disabled after 5s so it can phase through fields to the draw point.
    • Any orb auto-becomes collectable after 60s, even if it never hit the accelerator.
    • Orb value passes through ResourceManager's additive (+10/level) then multiplicative (×2, ×4) modifiers, truncated to int.
    Stratum II · currency

    Four resources, one formula

    Every gain runs through one gated path: gain = baseGain × n × Σ(additive) × Π(multiplicative), cast to int. Modifier stacks start at [1.0]; upgrades push more onto them.

    ⚠ Artifacts — the ghost resource ResourceType.Artifacts exists and the win screen will print a lifetime total for it, but nothing in the game ever increments it and no upgrade costs it. It's a cut/vestigial fourth resource — a hook the sequel could revive, or quietly delete.
    Stratum III · the ledger

    Economy & upgrade explorer

    All 29 upgrades, exact from UpgradeManager.Reset(). Cost scales geometrically: cost(n) = ⌊scalen × base⌋ where n = times already purchased. Filter, search, then click any upgrade for its cost curve and dependencies.

    The dependency tech-tree

    Solid edges are visible prerequisites (you see the upgrade, greyed, before you can afford its parent); dashed edges are hidden requirements (the upgrade stays invisible until its parent is bought).     Stratum IV · the library

    The distillery

    A literal bucket conveyor draws Cognitio Aqua Diluta from the depths and distills it into Science. It's a clean throughput chain with three knobs.

    Situla · max 100

    Buckets

    Each filled bucket reaching the top = +1 goo. Chain starts with 8; more = more parallel arrivals.

    Aliquid · max 3

    Chain speed

    chainSpeed ×2 per level → 5, 10, 20, 40 (base 5). Faster loop = faster arrivals.

    Studeo · max 3

    Efficiency

    goo-per-Science ÷2 per level → 64, 32, 16, 8 (base 64). Cheaper batches.

    ∑ Science rate The chain is a 10-unit loop; a bucket arrives, adds 1 goo, and every gooToMakeKnowledge goo distills into exactly 1 Science. Steady state:

    Science/s ∝ ( buckets × chainSpeed ) ÷ gooToMakeKnowledge

    Fully maxed vs. base ≈ (N buckets) × 8 (chain) × 8 (efficiency). Science is the gate-key currency: every late-game unlock (Imbumentum, Sturdier Supports, the Gate story, the Cathedral) is priced in it.

    Stratum V · the reckoning

    People, the Gate & the end

    Houses make people; the gate eats them. The endgame is a brutal rate race — and a moral one.

    Supply

    New Gloomhollow

    Cottages (+1, max 20) and Flats (+2, max 16) grant people on build and pepper the skyline (balanced across ledges, max 6 each). Extended Flock turns on passive generation (every ~2s per home); Fecund Harvest doubles it with a +1 additive modifier.

    Demand

    The sacrifice line

    Each Ritekeeper (max 8) speeds the cadence: a people.yeet.request fires every 1.0 / ritekeepers seconds. The Cathedral spends 1 person and launches a ragdoll soul down the pit (2 with Twin Reaping Rite). Souls funnel through a suction trigger into the gate's maw.

    ⚠ The leaky-bucket gate Gate progress rises +0.025 per soul but decays −0.355 / second, opening at 1.0. You must land souls faster than they bleed off — roughly ≥15 souls/second sustained (14.2 exactly). ⌖ These are the real values lifted from the prefab YAML; the C# defaults of 0.1 / 1.0 were placeholders. This single relationship is the difficulty of the entire endgame.

    The ending

    1. Gate opens → onOpenGate → publishes game.triggerEndCinimatic.
    2. A bat swarm erupts (spawn rate cranked 50 → 200/s), the camera dives, music swells (4.75s).
    3. A hand rises from the gate; three lines fade in — "At long last / free from the depths / again…" (5s).
    4. gameManager.showWin → the win screen tallies your lifetime Mako / People / Science.
    Stratum I · signals

    The pub/sub nervous system

    Systems never call each other directly across boundaries — they shout into the bus. These are the 13 code-published topics; many subscribers are wired in-scene as PubSubListener components (flagged below). Reproducing this loose coupling cleanly is most of the port's "feel."

    Stratum 0 · scaffolding

    Scenes, build & serving

    A persistent root scene boots everything; gameplay scenes load additively on top and are swapped via the bus.

    Build pipeline

    WebGL today, already

    build.sh batch-builds macOS / Linux / Windows / WebGL via a custom WebGLBuilder.BuildGame. Template = PWA, Gzip compression, Wasm, 16 MB initial memory. So a Unity-WebGL build exists — but it ships the whole engine runtime. The goal here is to leave that behind.

    Serving

    nginx + docker

    unity-nginx.conf serves pre-compressed .gz assets with the right Content-Encoding and a one-line run-docker.sh mounts it into stock nginx. Canvas default 1320×760. A static HTML5 port would need none of this gz dance — just a plain static host.

    The ascent · out of Unity

    Porting blueprint

    The goal: a pure web build, no Unity runtime. The good news — this game is small, dependency-light, and 2D. The hard parts are narrow and known.

    Recommended stack

    Render + world

    PixiJS (WebGL) + TypeScript

    Pixi exists for exactly this problem: thousands of batched sprites. The Mako cloud is the one rendering challenge and Canvas2D would choke on it; Pixi's sprite batching eats it. TypeScript pays for itself on the 29-node upgrade graph and modifier math.

    UI

    HTML / CSS DOM overlay

    The upgrade list, tooltips, HUD, and odometer were built in Unity's uGUI — i.e. a retained-mode UI tree. Rebuild them as DOM over the Pixi canvas: you get text, layout, scrolling, hover, and accessibility for free instead of reinventing them in WebGL.

    Physics

    Hand-rolled, fixed-timestep

    Don't pull in matter.js. The physics is shallow — up-force fields, spawn impulses, PD "seek" controllers, and AABB triggers. A ~150-line fixed-step (to mirror Unity's FixedUpdate) integrator gives exact control to reproduce the float/swirl feel, and pools orbs to dodge GC.

    Glue

    Tiny event emitter + WebAudio

    Re-implement JamKit's PubSub as a ~30-line typed EventBus. Wrap WebAudio in an AudioManager with a small voice pool (the original uses 64). Add localStorage save — the one feature the original lacks and the sequel wants.

    Alternatives weighed: Phaser (great, but pushes UI into the canvas — wrong for this text-heavy UI, and heavier to "fully detach"); vanilla Canvas2D (smallest deps, but you'd hand-write the sprite batching the Mako cloud needs). PixiJS+DOM is the sweet spot for "detach from Unity, keep the feel, ship static."

    phasing

    • 2 · Mako loop — Pixi stage, orb pool + physics, harvester/collector, the field. Prove the cloud renders.
    • 3 · UI shell — DOM upgrade list bound to the bus, HUD, tooltips, odometer, camera-depth scroll.
    • 4 · Layers — refinement, distillery, people, gate + endgame, intro/tutorial.
    • 5 · Polish — audio, save/load, a real leaderboard backend, dissolve shaders (or CSS fallback).
    ⌖ Two things to settle before coding (1) The leaderboard never worked — AddScore submits a hard-coded 102 and only appears in a test scene. (2) Scene-wired events — the exact "publish X → call Y" map lives in .unity/.prefab YAML, not code. Lift it once into a pubsub map data file; it's the connective tissue of the whole game.
